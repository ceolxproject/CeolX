# Task 3: Authentication Sessions and OAuth Tables

## Description

Configure BetterAuth-compatible session management tables for the Mentor platform. This includes database-backed sessions with role-based expiry times, OAuth provider accounts, and email verification/password reset token tables. These tables enable secure authentication across multiple platforms (web learner, web mentor, web admin, mobile) with different session durations based on user role.

## Affected Apps/Packages

- `packages/auth` (BetterAuth configuration)
- `packages/db` (schema definition)
- `apps/api` (session validation)
- `apps/web-learner` (learner auth flow)
- `apps/web-mentor` (mentor auth flow)
- `apps/web-admin` (admin auth flow)
- `apps/mobile` (mobile app sessions)

## Requirements

### Sessions Table (BetterAuth Database-Backed)

Create table `sessions` with the following columns:

| Column             | Type           | Constraints                | Description                                         |
| ------------------ | -------------- | -------------------------- | --------------------------------------------------- |
| `id`               | `VARCHAR(255)` | PK, NOT NULL               | Unique session identifier (generated by BetterAuth) |
| `user_id`          | `UUID`         | FK → users(id), NOT NULL   | Link to authenticated user                          |
| `token`            | `VARCHAR(255)` | NOT NULL                   | Hashed session token (never expose plaintext)       |
| `expires_at`       | `TIMESTAMP`    | NOT NULL                   | Session expiration time (UTC)                       |
| `ip_address`       | `INET`         | NULL                       | IP address of session origin (for security audits)  |
| `user_agent`       | `TEXT`         | NULL                       | User-Agent string (for device identification)       |
| `created_at`       | `TIMESTAMP`    | NOT NULL, DEFAULT: `now()` | Session creation timestamp                          |
| `last_activity_at` | `TIMESTAMP`    | NOT NULL, DEFAULT: `now()` | Last activity timestamp (for inactivity timeout)    |
| `revoked_at`       | `TIMESTAMP`    | NULL                       | When session was explicitly revoked                 |

### Session Expiry Strategy

- **Learner sessions**: 30 days from creation (`expires_at = now() + interval '30 days'`)
- **Mentor sessions**: 30 days from creation (same as learner)
- **Admin sessions (Super Admin)**: 24 hours from creation (`expires_at = now() + interval '24 hours'`)
- **Inactivity timeout**: 7 days for all roles (track in `last_activity_at`)
- Implement session refresh: allow session extension on activity if not within 24 hours of expiry

### Indexes for Sessions Table

- Primary Key: `id`
- Index: `(user_id)` - for user session lookups
- Index: `(token)` - for fast session token validation
- Index: `(expires_at)` - for cleanup queries (delete expired sessions)
- Index: `(user_id, expires_at)` - composite for active session checks
- Index: `(revoked_at)` - for finding revoked sessions

### Accounts Table (OAuth Providers)

Create table `accounts` for OAuth provider credentials:

| Column                | Type           | Constraints                | Description                                   |
| --------------------- | -------------- | -------------------------- | --------------------------------------------- |
| `id`                  | `VARCHAR(255)` | PK, NOT NULL               | Unique account link identifier                |
| `user_id`             | `UUID`         | FK → users(id), NOT NULL   | Link to user account                          |
| `account_type`        | `VARCHAR(50)`  | NOT NULL                   | Enum: 'google', 'apple', 'credentials'        |
| `provider_account_id` | `VARCHAR(255)` | NOT NULL                   | OAuth provider's user ID                      |
| `provider_name`       | `VARCHAR(50)`  | NOT NULL                   | Name of provider (Google, Apple, etc.)        |
| `access_token`        | `TEXT`         | NULL                       | OAuth access token (encrypted in production)  |
| `refresh_token`       | `TEXT`         | NULL                       | OAuth refresh token (encrypted in production) |
| `id_token`            | `TEXT`         | NULL                       | OpenID token if available                     |
| `token_expires_at`    | `TIMESTAMP`    | NULL                       | When OAuth token expires                      |
| `scope`               | `TEXT`         | NULL                       | Granted OAuth scopes (comma-separated)        |
| `created_at`          | `TIMESTAMP`    | NOT NULL, DEFAULT: `now()` | Account link creation                         |
| `updated_at`          | `TIMESTAMP`    | NOT NULL, DEFAULT: `now()` | Last update timestamp                         |

### Unique Constraint for Accounts

- Composite unique index: `(user_id, account_type, provider_name)` - one account per provider per user
- Unique index: `(provider_name, provider_account_id)` - prevent duplicate OAuth links

### Indexes for Accounts Table

- Primary Key: `id`
- Index: `(user_id)` - for finding user's OAuth accounts
- Unique Index: `(provider_name, provider_account_id)` - OAuth provider uniqueness
- Index: `(account_type)` - for filtering account types

### Verification Tokens Table

Create table `verification_tokens` for email and other verification flows:

| Column       | Type           | Constraints                | Description                                |
| ------------ | -------------- | -------------------------- | ------------------------------------------ |
| `id`         | `UUID`         | PK, Default: `uuid_v7()`   | Unique token identifier                    |
| `token`      | `VARCHAR(255)` | UNIQUE, NOT NULL           | Hashed verification token                  |
| `user_id`    | `UUID`         | FK → users(id), NOT NULL   | User being verified                        |
| `email`      | `VARCHAR(255)` | NOT NULL                   | Email address being verified               |
| `token_type` | `VARCHAR(50)`  | NOT NULL                   | Enum: 'email_verification', 'email_change' |
| `expires_at` | `TIMESTAMP`    | NOT NULL                   | Token expiration (typically 24 hours)      |
| `used_at`    | `TIMESTAMP`    | NULL                       | When token was successfully used           |
| `created_at` | `TIMESTAMP`    | NOT NULL, DEFAULT: `now()` | Token creation timestamp                   |

### Indexes for Verification Tokens Table

- Primary Key: `id`
- Unique Index: `(token)` - for fast token lookup
- Index: `(user_id)` - for finding user's tokens
- Index: `(email)` - for finding tokens by email
- Index: `(expires_at)` - for cleanup queries

## Technical Notes

### Session Token Security

- Tokens should be hashed using bcrypt or SHA-256 before storage
- Never store plaintext tokens in database
- BetterAuth provides token hashing automatically
- Compare hashed tokens during validation, not plaintext

### Session Expiry Logic

- Query active sessions: `SELECT * FROM sessions WHERE expires_at > NOW() AND revoked_at IS NULL`
- Cron job or background task should delete expired sessions daily
- Consider archiving sessions to separate table before deletion for audit trail

### OAuth Token Encryption

- In production, encrypt access_token, refresh_token, and id_token before storage
- Use field-level encryption or transparent database encryption
- Never log or expose OAuth tokens in error messages
- Implement secure key rotation for encryption keys

### Rate Limiting Tokens

- Track failed token validations to prevent brute force
- Implement exponential backoff after repeated failures
- Log suspicious token validation patterns for security monitoring

### BetterAuth Integration

- Session table structure must match BetterAuth PostgreSQL adapter spec
- Token field should store hashed session token, not plaintext
- user_id must be UUID matching users table
- BetterAuth may add additional internal fields; don't remove them

### Account Linking Flows

- Users can link multiple OAuth providers to same account
- Prevent linking same provider twice to same account
- Display linked providers on user settings page
- Allow unlinking with appropriate confirmation

### Verification Token Strategy

- Email verification tokens expire after 24 hours
- Password reset tokens expire after 1 hour
- Use cryptographically secure random token generation (e.g., `crypto.randomBytes(32).toString('hex')`)
- Never reuse tokens; generate new ones on each request

### Indexes for Performance

- Composite index on (user_id, expires_at) enables fast session lookups
- Index on expires_at enables efficient cleanup queries
- Index on token enables O(1) token validation
- Consider partial indexes for commonly filtered states (e.g., active sessions)

### Cleanup Strategies

Create automated cleanup processes:

- **Sessions**: Delete records where `expires_at < NOW() - INTERVAL '7 days'` weekly
- **Verification tokens**: Delete records where `expires_at < NOW()` daily
- **Password reset tokens**: Delete records where `expires_at < NOW()` hourly or daily

### Inactivity Timeout

- Track `last_activity_at` on each API call that uses session
- Sessions expire if `NOW() > last_activity_at + INTERVAL '7 days'`
- Allow session refresh if within 24 hours of expiry
- Refresh creates new session without interrupting user experience

### Testing Considerations

- Test session creation with correct expiry times for different roles
- Test expired session rejection
- Test OAuth account linking and delinking
- Test token validation with correct hashing
- Test cascade delete when user is deleted
- Test concurrent session handling for same user
- Test token reuse prevention

### Security Audit Logging

- Log all session creation, usage, and revocation for audit trails
- Include ip_address and user_agent for anomaly detection
- Monitor for impossible travel (session from different countries in short timeframe)
- Alert on high volume of session creations for same user
