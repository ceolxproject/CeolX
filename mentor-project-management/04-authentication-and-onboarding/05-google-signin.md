# Google Sign-In

## Description

Implement Google OAuth 2.0 integration via BetterAuth. Support both new account creation and existing account linking. Handle profile data extraction (name, email, photo URL). Support multiple platforms: web apps (popup/redirect flow), and mobile app (expo-auth-session).

## Affected Apps/Packages

- `packages/auth`
- Frontend: All three web apps and mobile
- Backend: Hono API with BetterAuth OAuth integration

## API Endpoints

### GET /auth/google

Initiate Google OAuth flow (web apps).

**Query Parameters**:

- `redirect_uri`: Where to send user after auth (optional, uses default)
- `state`: CSRF token (generated by BetterAuth)

**Behavior**:

- Redirects to Google login if not authenticated
- Redirects to consent screen if account needs authorization
- Returns to `redirect_uri` with authorization code

### POST /auth/google/callback

Handle Google OAuth callback (internal, handled by BetterAuth).

**Query Parameters**:

- `code`: Authorization code from Google
- `state`: CSRF token for validation

**Response** (Redirects to frontend with session):

```
Redirect to: <FRONTEND_URL>?status=success or ?status=error
Set-Cookie: authToken=<session_token>
```

### GET /auth/user/oauth-providers

Get linked OAuth providers for current user.

**Response** (200 OK):

```json
{
  "providers": [
    {
      "provider": "google",
      "linkedAt": "2024-02-18T10:30:00Z",
      "email": "john@example.com",
      "displayName": "John Doe"
    }
  ]
}
```

## Requirements

### Google OAuth Configuration

- Register app in Google Cloud Console
- OAuth 2.0 credentials: Client ID and Client Secret
- Authorized redirect URIs:
  - `https://api.example.com/auth/google/callback` (production)
  - `http://localhost:3000/auth/google/callback` (development)
  - Native app scheme: `mentor://oauth/google` (mobile)
- Store credentials in environment variables
- Configure scopes: `openid profile email`

### BetterAuth Google Provider Configuration

```typescript
// In packages/auth/src/config.ts
oauth: {
  providers: [
    {
      id: 'google',
      name: 'Google',
      type: 'oidc',
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      discoveryUrl: 'https://accounts.google.com/.well-known/openid-configuration',
      scopes: ['openid', 'profile', 'email'],
    },
  ],
}
```

### Account Creation Flow

- User initiates Google Sign-In
- Google returns email, name, and picture URL
- **New User**:
  - Create user account with email from Google
  - Set name from Google profile
  - Set `emailVerified: true` (Google verifies email)
  - Create `account` record linking Google provider
  - Default role: `learner`
- **Existing User**:
  - Check if user with email exists
  - If yes, link Google account to existing user (federated identity)
  - Only create new account if email doesn't exist

### Account Linking

- Support linking Google to existing email/password account
- Require re-authentication if session > 15 minutes old
- Display confirmation: "Link Google to your account?"
- Store in `account` table:
  - `userId` (foreign key)
  - `provider`: 'google'
  - `providerAccountId`: Google's user ID
  - `displayName`, `email`, `image`
  - `linkedAt` timestamp

### Profile Data Extraction

- Extract from Google ID token:
  - `email`: User's email
  - `name`: Full name
  - `picture`: Profile photo URL
  - `email_verified`: Boolean (always true for Google)
- Store picture URL in user `image` field
- Default to Postmark avatar or initials if no picture

### Session Creation

- Follow same session creation as email/password signin (task 04)
- Set session expiry: 30 days learner, 24 hours admin
- Store user agent and IP address
- Set secure cookies with HttpOnly, Secure, SameSite

### Web Implementation (Next.js)

**Popup Flow** (Recommended):

- Use `next-auth` library or custom OAuth client
- Open OAuth URL in new window
- Listen for postMessage from popup
- Close popup and redirect on success
- Handle user cancellation

**Redirect Flow** (Alternative):

- Redirect to `/auth/google` endpoint
- After auth, redirect back to referrer or dashboard

### Mobile Implementation (React Native Expo)

**Using expo-auth-session**:

- Install `expo-auth-session` and `expo-random`
- Create custom OAuth client
- Use `AuthSession.startAsync()`
- Handle deep link callback with custom URL scheme
- Store token in SecureStore

**OAuth Configuration**:

```typescript
// packages/auth/src/expo-google.ts
import * as AuthSession from "expo-auth-session";
import * as SecureStore from "expo-secure-store";

const redirectUrl = AuthSession.makeRedirectUrl({
  native: "mentor://oauth/google",
});

export async function signInWithGoogle() {
  const [request, response, promptAsync] = Google.useAuthRequest({
    clientId: process.env.GOOGLE_CLIENT_ID_MOBILE,
    redirectUrl,
    scopes: ["profile", "email"],
  });

  const result = await promptAsync();
  if (result?.type === "success") {
    const { access_token } = result.params;
    // Send to backend to create/link account
    return exchangeTokenForSession(access_token);
  }
}
```

### Error Handling

- User cancels auth: Show message, return to login
- Invalid client credentials: Log error, show generic message
- Network error: Retry with exponential backoff
- Email already linked to other account: Ask user to sign in with that method
- Account linking failure: Show clear instructions

## Technical Notes

### BetterAuth OAuth Flow

BetterAuth handles full OAuth flow internally:

1. Generate CSRF token (state)
2. Redirect to Google with client ID, scopes, redirect URI
3. Receive authorization code at callback endpoint
4. Exchange code for access token
5. Fetch user info from Google
6. Create or link user account
7. Create session and set cookies
8. Redirect to frontend with success status

### Database Schema - Account Linking

// pages/auth/google/callback.tsx
'use client';

import { useEffect, useSearchParams } from 'next/navigation';
import { useRouter } from 'next/navigation';

export default function GoogleCallback() {
  const router = useRouter();
  const searchParams = useSearchParams();

  useEffect(() => {
    const status = searchParams.get('status');

    if (status === 'success') {
      router.push('/dashboard');
    } else if (status === 'error') {
      const error = searchParams.get('error');
      console.error('Google auth error:', error);
      router.push('/auth/signin?error=google_failed');
    }
  }, [searchParams, router]);

  return <div>Authenticating...</div>;
}

### Mobile Implementation Example (Expo)

```typescript
// Mobile Google Sign-In
import * as SecureStore from "expo-secure-store";

async function signInWithGoogle(backend_url: string) {
  try {
    const result = await promptAsync();

    if (result?.type !== "success") {
      throw new Error("User cancelled authentication");
    }

    const { access_token, id_token } = result.params;

    // Exchange token with backend
    const response = await fetch(`${backend_url}/auth/google/mobile`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ idToken: id_token, accessToken: access_token }),
    });

    if (!response.ok) {
      throw new Error("Failed to authenticate with backend");
    }

    const { sessionToken, user } = await response.json();

    // Store session in secure storage
    await SecureStore.setItemAsync("authToken", sessionToken);

    return { user, sessionToken };
  } catch (error) {
    console.error("Google sign-in error:", error);
    throw error;
  }
}
```

### Account Linking Endpoint (POST /auth/link-provider)

```typescript
export async function handleLinkProvider(c: Context) {
  const user = c.get("auth.user");
  const session = c.get("auth.session");
  const { provider } = await c.req.json();

  if (!user) return c.json({ error: "UNAUTHORIZED" }, 401);

  // Check session age
  const sessionAge = Date.now() - session.createdAt.getTime();
  if (sessionAge > 15 * 60 * 1000) {
    // Session older than 15 min, require re-auth
    return c.json(
      {
        error: "REAUTHENTICATION_REQUIRED",
        message: "Please sign in again to link a provider",
      },
      403
    );
  }

  // Store linking intent
  const linkingToken = generateToken();
  await storeLinkinToken(user.id, provider, linkingToken);

  // Redirect to OAuth with linking flag
  return c.redirect(`/auth/${provider}?link=true&token=${linkingToken}`);
}
```

### Security Considerations

- Always validate `state` parameter to prevent CSRF
- Store `state` in session or short-lived Redis key
- Use PKCE for mobile apps (if supported by Google)
- Never store refresh tokens in client storage
- Refresh tokens should be server-side only
- Validate email domain if restricting to organizational emails
