## Description

Bootstrap the Drizzle schema file structure and define all PostgreSQL enum types before any tables are written. Enums must be declared first because table columns reference them — if they're scattered across table files, circular imports or ordering issues arise.

This task also wires up the schema barrel export so every subsequent schema file is auto-included.

---

## Affected Apps / Packages

- `apps/api/src/db/schema/` — new directory; one file per concern
- `apps/api/src/db/index.ts` — barrel export that re-exports `db` + all schema
- `packages/shared/src/types/enums.ts` — TypeScript enum mirrors for the mobile app and admin

### Shared TypeScript Enums (packages/shared)

Mirror the PostgreSQL enums as TypeScript `const` objects so the mobile app and admin can use the same values without depending on Drizzle:

```typescript
// packages/shared/src/types/enums.ts
export const UserRole = {
  Spectator: "spectator",
  Artist: "artist",
  Venue: "venue",
  SuperAdmin: "super_admin",
} as const;
export type UserRole = (typeof UserRole)[keyof typeof UserRole];

// ... repeat for EventStatus, BookingStatus, etc.
```

## Technical Notes

- Use `pgEnum` from `drizzle-orm/pg-core` — this generates `CREATE TYPE ... AS ENUM` in the migration
- Enum names in PostgreSQL are global per schema — prefix with context if needed (e.g. `booking_status` not just `status`) to avoid collisions
- PostgreSQL enums are **case-sensitive** — always lowercase to match the definitions here
- `const` objects + `typeof` pattern in shared is preferred over TypeScript `enum` keyword — it compiles to plain objects, works in React Native without any transpilation issues
