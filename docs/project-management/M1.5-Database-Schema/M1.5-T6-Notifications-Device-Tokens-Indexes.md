## Table Definitions

### `notifications`

| Column       | Type         | Constraints              | Notes                                            |
| ------------ | ------------ | ------------------------ | ------------------------------------------------ |
| `id`         | UUID         | PK, default random       |                                                  |
| `user_id`    | UUID         | NOT NULL, FK → users(id) | CASCADE on delete                                |
| `type`       | varchar(100) | NOT NULL                 | e.g. `event_approved`, `booking_invitation`      |
| `payload`    | JSONB        | NOT NULL                 | `{ persona, route, action? }` — see schema below |
| `read`       | boolean      | default false            |                                                  |
| `created_at` | timestamp    | NOT NULL, defaultNow     |                                                  |

**Index**: B-tree on `(user_id, read)` — supports unread count badge and filtered inbox.

**Payload shape** (TypeScript type in `packages/shared`):

```typescript
type NotificationPayload = {
  persona: 'spectator' | 'artist' | 'venue';
  route: string; // deep link: "/events/123", "/bookings/456"
  action?: string; // optional CTA label: "View Event", "Accept Booking"
  title: string; // push notification title
  body: string; // push notification body text
};
```

### `device_tokens`

| Column       | Type            | Constraints              | Notes                           |
| ------------ | --------------- | ------------------------ | ------------------------------- |
| `id`         | UUID            | PK, default random       |                                 |
| `user_id`    | UUID            | NOT NULL, FK → users(id) | CASCADE on delete               |
| `fcm_token`  | text            | NOT NULL                 | Firebase FCM registration token |
| `platform`   | `platform` enum | NOT NULL                 | `ios` or `android`              |
| `created_at` | timestamp       | NOT NULL, defaultNow     |                                 |
| `updated_at` | timestamp       | NOT NULL, defaultNow     |                                 |

**Unique constraint**: `(user_id, fcm_token)` — prevents duplicate token registrations per device. FCM tokens can change after app reinstall; upsert via `ON CONFLICT (user_id, fcm_token) DO UPDATE SET updated_at = NOW()`.

## Common Gotchas

- **JSONB vs JSON for payload**: Use `jsonb` — it's binary-indexed, supports GIN indexes, and enables `->` / `#>` operators for querying inside the payload. `json` stores raw text and is slower for reads.
- **FCM token rotation**: FCM tokens are not permanent. When a device sends a new token on app open, upsert it: `INSERT ... ON CONFLICT (user_id, fcm_token) DO UPDATE SET updated_at = NOW()`. Old tokens should be cleaned up when FCM returns an `UNREGISTERED` error.
- **`type` as varchar not enum**: Notification types will evolve as features are added across milestones. Using varchar avoids enum migration pain. Keep a list of valid types as a TypeScript `const` in `packages/shared`.
