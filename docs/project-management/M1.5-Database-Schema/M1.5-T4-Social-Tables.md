## Description

Define the four social tables. These are relatively straightforward but require careful attention to soft-delete patterns (posts, comments) and idempotency constraints (likes, follows).

| Column       | Type      | Constraints              | Notes             |
| ------------ | --------- | ------------------------ | ----------------- |
| `id`         | UUID      | PK, default random       |                   |

## Key Design Decisions

- **Soft delete via `deleted_at`**: Posts and comments are never hard deleted. API layer filters `WHERE deleted_at IS NULL` for normal queries. Deleted comments display as "Comment deleted" — the row is retained so reply threads remain coherent.
- **`like_count` denormalization on posts**: Real-time COUNT of `post_likes` would be expensive on a feed sorted by popularity. Denormalized counter is incremented/decremented atomically alongside the `post_likes` insert/delete. Risk: drift if a transaction fails mid-way — accept this for V1 scale (<1,000 users).
- **`follows` self-referencing users**: Both `follower_id` and `followee_id` FK to `users`. A user cannot follow themselves — enforce this at the application layer (not a DB check constraint in V1).
- **No comment threading in V1**: Comments are flat. No `parent_id` column. Keep it simple.
- **No media storage in this table**: `media_url` is an S3/CloudFront URL. The actual upload/transcode flow is M10. Schema just stores the final URL.

## Common Gotchas

- **Soft delete queries**: Every query touching `posts` or `comments` in the API layer must include `WHERE deleted_at IS NULL`. Consider adding a Drizzle query helper or view for this.
- **Like count drift**: The atomic pattern is: `BEGIN; INSERT INTO post_likes ...; UPDATE posts SET like_count = like_count + 1 WHERE id = ...; COMMIT;` — wrap in a transaction. On unlike: decrement and guard against going below 0 (`GREATEST(like_count - 1, 0)`).
- **Follows cascade**: If a user is deleted, their follow relationships are CASCADE deleted. This is correct — no orphaned follows.
