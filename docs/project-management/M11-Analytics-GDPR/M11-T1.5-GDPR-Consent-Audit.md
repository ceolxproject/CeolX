## Description

The remaining three GDPR requirements that did not ship with M11-T1's account-deletion work. These are smaller, surface-level pieces but mandatory for an Irish client at launch. Each can be tackled independently; R1+R2 naturally batch into a single PR (they share a screen).

The original M11-T1 spec is now **complete** as far as R3 (Right to Erasure) and R6 (24-month inactivity flag) are concerned — both shipped in PR #52. The work below is what's left.

---

## Requirements

### R1 — Consent checkboxes at sign-up

Mobile sign-up flow must surface three opt-in checkboxes (NOT pre-checked):

- "I consent to data collection (profile info, listening history)"
- "I allow location access for event discovery"
- "I opt-in to marketing emails and offers"

Server-side persistence is **already done** — `users.completeRegistration` writes `consent_at` (timestamp) and `marketing_consent` (boolean) to the user row. The work here is purely the mobile UI step that captures the three flags before calling the mutation.

### R2 — Privacy Policy + ToS acceptance

The same consent screen must include:

- A required "I have read and accept the Privacy Policy and Terms of Service" checkbox
- Inline links to the live Privacy Policy and Terms of Service pages
- The "Accept & Continue" button is disabled until the checkbox is ticked

**Blocked on legal copy** — the Privacy Policy and Terms of Service documents must be drafted, signed off, and hosted (most likely under `ceolx.com/privacy` and `ceolx.com/terms`, served from `apps/admin`) before this can ship. Flag this as a legal/client dependency early.

### R5 — On-demand location only

Audit the mobile app to confirm `expo-location` is only invoked when the map screen is active — no background tasks, no `expo-task-manager` location subscriptions, no startup-time location reads.

This is **likely already compliant** thanks to the M3-T2 location permission fallback. The audit is a 30-min sanity pass — grep for `expo-location` and `Location.startLocationUpdates`, document the findings, mark R5 closed if nothing background-y is found.

## Acceptance Criteria

- [ ] **R1** — Sign-up consent screen renders three opt-in checkboxes; none pre-checked; the three booleans are captured and persisted via `users.completeRegistration` (extending the input schema with `dataCollection` if it's not already implied by `consent_at`)
- [ ] **R2** — Same screen requires "I have read and accept Privacy Policy + ToS"; "Accept & Continue" button disabled until ticked; tapping the link opens the hosted Privacy / Terms page in-app or in a webview
- [ ] **R2 (legal)** — Privacy Policy and Terms of Service drafts signed off by Pratiksha / client, hosted at `ceolx.com/privacy` and `ceolx.com/terms`
- [ ] **R5** — Repo audit confirms no background-location code paths; `expo-location` only invoked from map screens; finding documented in this task or the M3-T2 spec

## Out of scope

- Consent withdrawal UI (a "Consent Settings" page where users can update opt-ins without deleting their account). GDPR strictly requires this _eventually_, but the original PRD did not call it out for V1; capture as a separate ticket if it surfaces in QA.
- Analytics opt-out toggle in the mobile app — only relevant once analytics are wired (M11-T2/T3 territory).

## Common Gotchas

- **Privacy Policy must be live before launch.** Easy to forget until App Store review flags it. Treat as a P0 launch blocker.
- **Pre-checked boxes are non-compliant under GDPR.** All three R1 checkboxes must default to false.
- **Don't conflate `consent_at` with R2 acceptance.** `consent_at` is currently set whenever `users.completeRegistration` runs — once R2 lands, that mutation should only run when R2 has been explicitly acknowledged.
- **Cookie/tracking consent is intentionally out of scope for V1** — `apps/admin` ships without web analytics, and the dashboard is internal-only (single Super Admin account). If analytics later get added to `apps/admin` (especially the public `ceolx.com/subscribe` page), a cookie banner will need to land in the same PR — the public subscribe page is hit by paying Artists / Venues, so EU consent rules still apply to those visitors.
